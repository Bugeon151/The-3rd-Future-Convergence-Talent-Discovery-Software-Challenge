# COMPETITION STRATEGY — 발표·심사 대응

## 1. 대회 테마에 대한 우리의 한 문장
> "사고는 **예측 가능함**. 우리는 충돌이 일어나기 **4초 전에**, 가장 안전한 행동을 **미리
> 시뮬레이션**해 추천하고, 그 행동이 실제로 사고를 막았는지 **계측**까지 하는
> **Counterfactual Predictive Safety OS**를 만들었습니다."

## 2. PERCEIVE → PREDICT → PREVENT → VERIFY 스토리 (발표 5분 구성)
1. **도입(30s)**: 산업 이동로봇/카트 ↔ 보행자 충돌 통계와 "사고 후 대응"의 한계.
2. **원리(2m)**: 위험을 '확률'로 표현, 카운터팩추얼(가상 개입) 시뮬레이션을 매 프레임 수행.
3. **데모(2m)**: `demo_avoided` 라이브 — 위험 49 도달 → `VEHICLE_RIGHT` 추천 → 실행 → PREVENTED.
4. **증명(30s)**: 평가표 (recall 1.0, lead 1.52s, 거짓경보 1, 개입성공 1.0, 위험감소 45.7).
5. **한계와 확장(30s)**: 솔직한 한계 3가지 + 향후 계획.

## 3. 강조 포인트 (심사위원 인상)
- **안전 판단에 LLM 미사용** — 결정적 기하/확률 파이프라인. "AI 포장 마케팅"이 아니라
  검증 가능한 엔지니어링.
- **폐쇄 루프 검증이 핵심 차별점** — 대부분의 시스템은 "경고"에서 끝남. 우리는 그 경고가
  사고로 이어졌는지 아닌지를 이벤트(PREVENTED)로 계측한다.
- **정직한 물리**: 정지가 불가능한 상황에서 정지 개입이 낮은 점수를 받는다는 것까지
  직접 보여줄 수 있다 = 하이퍼파라미터로 대충 맞춘 게 아니다.
- **불확실성 표현**: 단일 궤적이 아닌 샘플 집합으로 충돌확률을 계산.

## 4. 자주 나올 질문과 답변 (축약)
자세한 10문항: [JUDGE_QA.md](JUDGE_QA.md)
- "실제 로봇에서 증명했나?" → 아직 아님, 시뮬레이션 검증. 단 `Runner` 교체만으로
  모터/메시 신호 연결 가능 (ROADMAP의 1단계).
- "카메라 한 대로 전방위를 다 볼 수 있나?" → 아니오. 2D 지면+단일 뷰 가정, 멀티캠은 확장항.
- "자동 브레이크는 안 붙었나?" → 우리는 위험 1순위를 **예방(사람·관리자 개입)** 으로 보고
  경고→추천→확인 체계에 집중. 자율 급제동은 시뮬레이션에서 STOP_VEHICLE로 검증 중.
